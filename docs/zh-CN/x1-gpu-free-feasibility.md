# X1 完全端侧运行：可行性与迁移门槛

日期：2026-09-15；评估基于 `x1-native` / `5755ee0` 的代码和离线实验。
这是后续方案，不表示生产配置已经切换。本次评估保持 demo 停止。

执行结果见[端侧接入与验证](x1-npu-integration.md)。下文保留执行前的判断：后续已
完成四模型共同驻留和部分脱网验证，也发现抓取视觉判断未过关；不要把“尚未测试”
理解为当前仍无实验结果。

## 1. 判断

**不依赖 GPU 服务器完成 demo，已有可信的实现路径，值得进入集成验证。**
ACT、中文转写、人员检测和同一 VLM 的图文/纯文本推理均已在本机运行。
尚不能宣布完整任务可用：抓取成功判断未测试，多模型共同驻留、持续运行和实机
闭环也未验收。当前最大不确定性是判断质量与系统集成，不是 ACT 单模型吞吐。

这里的完全端侧是 NPU 执行主要神经网络，CPU 负责 ROS、导航、控制、音视频采集
和必要的前后处理。目标为运行时不访问远程 GPU；训练和模型准备可以继续离线使用
其他机器。模型迁移不自动增加 ACT 对新物体的泛化能力。

## 2. 候选组成及证据

| 功能 | 首选端侧实现 | 本机证据 | 尚缺验证 |
| --- | --- | --- | --- |
| 唤醒与提示 | 沿用轻量唤醒，固定 WAV | 已有实现 | 接入新 ASR 后收音/播放互斥 |
| 中文指令转写 | Whisper-base W8A16 / AidLite | 三段音频各重复三次，每段均值 0.144–0.228 秒 | 真实噪声、开放物品名、静音拒识的在线表现 |
| 人员检测 | YOLOv8n W8A8 / AidLite | 3 Hz 三轮，平均 11.28 ms，进程 CPU 约单核 3.38% | 室内距离、遮挡与深度/TF 联动 |
| 意图与开放物品框选 | 同一个 Qwen2.5-VL-3B W4A16 / AidGen | 意图平均 0.658 秒；框选平均 2.44 秒 | 生产协议、独立样本、框中心深度准确性 |
| 抓取成功判断 | 上述同一个 VLM，独立提示与验证协议 | 尚未测试 | 空夹、接触未抓住、错物、遮挡、离桌夹持 |
| 抓取动作推理 | 现有 ACT 权重 / ORT QNN HTP FP16 | 完整 100×6 动作块约 14.99 ms；无 CPU 回退 | 长轨迹、夹爪闭合边界、闭环执行 |

IoU 粗筛，仍有漏框物体部分的问题。ACT 的七个观察最大绝对差约 0.001675，
误差单位随关节而异；速度和数值接近不能代替实机抓取成功率。
详细原始口径见[首轮实验](x1-npu-experiments.md)和[VLM/ACT 实验](x1-npu-vlm-act-experiments.md)。

保留开放指令和开放物品名。小人员检测器只负责找人，不用它的有限类别表限制取物。
当前 `detect_object_node.py` 的 ACT 分支通过 VLM 框中心附近深度得到目标，不调用
经典分支的 SAM2/GPD。X1 的 ACT 专用运行配置应取消这些服务的强制启动、探活和
依赖要求，不必先将 SAM2/GPD 搬到 NPU。现有深度有效性检查仍保留。

## 3. 运行组织

保留现有 ROS 任务与控制结构，只增加具体本地推理后端，不建设通用推理框架。

- VLM 只加载一套权重，三个业务使用不同提示与严格结果校验。
- ACT 用独立 Python 3.12 工作进程，保留现有输入/动作契约。ROS Python 3.10
  环境不直接安装实验 ORT 依赖；先复用回环接口，再根据测量决定是否减少 JPEG/复制。
- AidLite 的 ASR/检测与 AidGen、ORT 分进程，隔离 Python 和运行库差异。
  分进程不保证底层 DSP 资源互不影响，仍需共同加载与切换试验。
- 模型尽量加载一次并预热，按需推理。ACT 每次冷加载/编译约 14.3 秒，不能每次
  抓取临时启动。缓存可作为实验项，当前没有缓存加载收益的证据。
- 按阶段安排 NPU：唤醒后 ASR → VLM 意图 → 导航 → VLM 找物 → ACT 抓取 →
  VLM 验证 → 人员检测与递送。导航和控制持续按既有频率工作。
- 抓取期间不新发起耗时 VLM 请求；阶段切换应等已有推理结束或使其结果失效。
  不假设 SDK 支持抢占正在执行的 VLM。任务期间继续暂停听新指令，网页取消保留。
- 请求关联任务和观察时间，限制排队；取消、超时和跨任务的旧结果不能进入动作队列。
  VLM 返回前机器人或物体发生移动时，必须重新观察，不能使用旧框直接动作。

## 4. 必须补齐的四道门槛

### A. 判断质量

先固定独立测试集再调整提示，分别测意图、框选和抓取验证。意图需使用生产的
`fetch_deliver`、物品、来源、接收者与置信度契约；实验的 `{intent, object}`
不能直接证明现有解析器可接受。取消、否定、闲聊、指代不清不得错误触发取物。
模型自报置信度也不能替代实测正确率。

框选不仅检查 IoU，还要检查中心是否落在目标上、对应深度是否属于目标、缺失目标
是否正确拒绝。抓取验证重点统计“没抓住却报成功”；已有腕部单帧无法证明夹持时
返回无法确认并阻止递送。可实验抬升前后两帧及现有关节反馈作为辅助，不能把
“夹爪闭合了”当作成功证据。单帧/双帧方案均需实际标签验证。

### B. 多模型与脱网环境

同时加载四套模型，按任务顺序反复交替运行，改变加载顺序并测试故障恢复。
记录整机可用内存、共享/DSP 分配、CPU、推理 p95/p99、温度和持续运行后的时延。
VLM 尚无可靠峰值内存数据，不能用模型文件大小或各进程 RSS 之和代替整机预算。

固定验证过的模型哈希与 SDK 组合；处理 ORT 的设备发现兼容问题、模型服务监听
地址和启动健康检查，不把实验临时设备链接当作部署完成。验证断开外网及远程
推理服务后冷启动、授权初始化和模型加载均可完成；若需要联网授权，应先解决
离线授权，再声称可独立运行。

### C. 接入与离线闭环

在 `x1-native` 上按可回退提交逐项接入：人员检测 → ASR → ACT → VLM 三项职责。
ACT 不再次量化为 INT8、不改分辨率、不改权重，先保留已经验证的 FP16 方案。
VLM 的坐标缩放、空框、拒识和抓取验证由适配层明确处理，不隐藏异常输出。

`tools/setup`、`tools/doctor`、`tools/run` 按本地后端检查依赖，替换当前 LM Studio
特定版本锁定及远程服务要求。独立运行配置禁止静默回退远程 GPU；模型失败应
返回明确错误，由现有任务取消/停止流程处理。固定资源和机器设置继续放忽略目录。

使用软件测试和已有录像检查协议、归一化、图像新鲜度、动作顺序、队列饥饿与取消。
补 ACT 连续轨迹及夹爪阈值附近样本，与原策略逐步比较。所有无人实验禁止打开
电机设备；实际控制入口仍必须显式包含 `--hardware`。

### D. 整机验收

先完成 30 分钟待机与 1 小时模拟阶段切换，再安排有人监护的至少十轮不同物品/
位置取物递送，覆盖取消、未找到和抓取失败。比较原有后端的任务结果与控制超时，
不把原有定位/夹爪问题算作 NPU 迁移成功或自动归因于迁移。

CPU 统一按整机在线六核为 100% 统计；以稳定待机平均与任务期间每个 10 秒窗口
平均低于 60% 为优化目标，同时保留冷启动数据。当前约 53.36% 是未定位待机基线，
不代表任务负载。ASR/检测原本按需运行，ACT/VLM 原本在远端；不能把单模型 CPU
节省直接从待机值扣除。迁移 VLM 会增加本机工作，低于 60% 仍需独立验收。

## 5. 建议先做什么

下一轮先完成抓取验证离线集、生产意图协议测试和四模型共同驻留压力实验。
这三项不要求人在机器人旁，能以较低成本判断是否值得开始正式接入。
质量不过关时优先定位具体职责的问题，再尝试其他本地模型或分阶段观察；不为
追求最小参数量同时改变 ACT、导航与交互。通过上述门槛后逐项切换后端。

供应商路径可参考 [AidGen VLM 部署说明](https://docs.aidlux.com/en/software/tutorial/genai-dev/vlm_chat_aidgen)
及 [Qualcomm 维护的 ORT QNN 插件说明](https://github.com/onnxruntime/onnxruntime-qnn)。
这些文档说明部署接口，不证明本项目的多模型兼容性或任务可靠性；本评估的性能
判断以本机实验为依据。
