# X1 Demo 降负载实施与验证

本文保留独立原生分支重构前一轮的实施记录。后续网页、状态入口和相机路径已有调整，
当前实现以 [X1 原生分支记录](x1-native-implementation.md) 为准；经验与下一步见
[优化复盘](x1-optimization-retrospective.md)。

本轮保留原生 Ubuntu 22.04、现有远程 ACT/VLM、开放物品与开放指令。
不改变控制频率、地图、标定、定位门槛和碰撞监测。

## 已实施的行为

- X1 感知与 ACT 图像订阅随动作创建和释放。完成、异常和取消都清理缓存；
  新动作拒绝旧时间戳和上一代订阅的回调。模型不随每次动作重新加载。
- 相机保持打开。C++ `camera_health` 从图像头监测采集时间与接收时间，
  每秒发布两次 `/camera/health` 诊断。任务管理和网页不再接收大图检查在线状态。
- 当前部署的 ACT 服务报告仅需要 `observation.images.wrist`；适配器省去头图编码。
  `tools/doctor` 在启用该配置时核对远程输入契约，模型与动作数据不变。
- 网页视频默认关闭。打开时按相机共享一个订阅和编码缓存，最多 3 fps；
  最后一个客户端断开后销毁订阅，不继续编码。关闭窗口和无图像时断连均有测试。
- X1 关闭体素调试图，代价地图采用增量发布。导航生命周期与运动检查保持运行。
- 腕部图像队列在 X1 模式下深度为 1，V4L2 请求一个采集缓冲；时间戳取自读取前，
  不在解码结束后给帧重新赋予更晚的时间。它仍是主机采集时间，并非硬件曝光时间。

## 固定语音

保留现有唤醒、Whisper 和意图解析；X1 默认使用两个 ASR 计算线程，关闭调试录音。
没有引入新的 ASR 模型。任务执行期间仍暂停收音，通过网页取消。

运行时只播放本地 stereo / 48 kHz / PCM16 WAV：

| 事件 | 提示 |
| --- | --- |
| 唤醒 | 我在，请说。 |
| 接受 | 好的，我去拿。 |
| 未理解 | 没听清，请再说一次。 |
| 完成 | 任务完成。 |
| 失败 | 任务失败，请查看页面。 |
| 取消确认 | 任务已取消。 |

六个文件已在部署阶段生成，位于忽略的本机音频目录，不进入版本库。
固定后端沿用 `SpeakText`，未配置文本返回错误，不回退到生成。
启动时检查格式与文件完整性；播放不启动 TTS、下载或 ffmpeg。
任务节点负责终态提示，避免语音入口重复播报，网页入口也获得相同提示。
终态播报失败只记告警，不把已经完成的机器人动作改判为失败。

## 启停、采样和回退

机器参数集中在忽略的 `config/local.yaml` 的 `demo` 段：

```yaml
low_load: true
managed_service: true
act_wrist_only: true
asr_threads: 2
wrist_camera_fps: 30.0
```

腕部正式配置保持 30 fps，15 fps 只有通过真实抓取对照后才启用。
ASR 两线程若在实测中明显变慢或无法稳定理解，可以改回 `asr_threads: 4`。

```bash
# 手动启动；会激活真实硬件并可能执行启动姿态。
tools/run demo --hardware
tools/run demo --status
journalctl -u xlerobot-demo -f

# 停止整个服务进程组，不需要运动授权标志。
tools/run demo --stop

# 只读采样，不打开电机或相机设备。
tools/doctor robot --profile --duration 60 --label demo-idle
```

服务通过 `tools/setup robot --install-demo-service` 安装，不启用开机启动，
不自动重启。进程按普通用户运行，`LimitRTPRIO=50` 允许控制器指定线程申请
实时调度；没有把整个进程或 AI 线程设置成 FIFO。停止使用 SIGINT 和整个 cgroup，
超时后清理残留子进程。

实施前已在忽略的 `.xlerobot/environment/x1-cpu-implementation-*` 保存工作区补丁和
原文件备份；其中本机配置与凭据的归档权限为 0600。不要用当前 Git HEAD 覆盖这些
既有迁移修改。按阶段回退应使用这份实施前备份。

`low_load: false` 可回退按需订阅、健康信息消费和固定播报；同时将
`act_wrist_only` 设为 false 可恢复双图请求。网页开关和导航显示配置需单独回退。

## 测量口径与验收状态

完整 demo 此前待机约 95.5%，停止后约 10%。这与本轮隔离相机测试不是同一工况，
不能直接相减来宣称完整 demo 已达到目标。

隔离实验使用独立 ROS 域，只启动 D455、腕部相机和图像消费者，不启动电机、
导航或真实任务。感知后端禁用，不执行模型推理；网页无人观看。
同一设备依次对照原订阅方式 30 fps、优化后 30 fps 和优化后 15 fps。
每组稳定后采样三次，每次 60 秒；原始 JSON、进程日志及复现脚本保存在忽略目录。
每个 JSON 包含系统 CPU、各进程 CPU、IRQ、温度、频率、CPU pressure 和网页健康状态。
进程 CPU 以一个核心为 100%，系统 CPU 以所有在线核心为 100%。

| 静态相机链路 | 三次整机 CPU 均值 | 组平均 |
| --- | --- | --- |
| 原订阅方式，腕部 30 fps | 44.66%、42.84%、43.57% | 43.69% |
| 按需订阅，腕部 30 fps | 26.36%、26.91%、25.33% | 26.20% |
| 按需订阅，腕部 15 fps | 22.22%、23.49%、23.16% | 22.95% |

保留 30 fps 时，相同静态测试的整机 CPU 下降约 17.49 个百分点，相对下降约 40%。
15 fps 不采用：180 个采样点中有 12 个腕部图像年龄超过 0.5 秒，最大约 1.75 秒；
30 fps 组没有超过 0.5 秒的采样点，最大约 0.40 秒。ACT 的图像新鲜度门槛是 0.5 秒。
这是基于主机采集时间的静态证据，不代表已经完成运动中的抓取回归。

软件验证包括按需订阅取消/超时、旧回调隔离、固定音频格式和直接播放、网页断连清理、
相机断流与恢复，以及无硬件的 Nav2 启动集成测试。服务已安装且保持 inactive。
独立的无硬件调度测试确认服务权限可让指定线程获得 FIFO 50，主线程保持普通调度；
真实控制器线程还需在现场启动后核验。
全部静态测试进程清理后，另采样 60 秒，整机 CPU 平均为 10.04%，正式网页端口未监听。

六条 WAV 已通过实际播放器逐条播放，播放进程均正常退出；听感仍待真人确认。
另用合成录音离线回放两条开放取物指令（羽毛球、杯子），两线程和四线程均正确转写并
通过现有置信门槛。两线程耗时约 4.97/4.24 秒，四线程约 6.66/6.11 秒，继续保留两线程。
同一次回放中唤醒模型识别到了“小乐小乐”。这只是功能检查，不是噪声场景或实机麦克风评测。
远程 ACT 也完成了一次只传腕图的 HTTP 检查，返回 100×6 的有效动作提议，未发送控制命令。

完整 demo 待机 ≤35%、任务 10 秒窗口平均 ≤75% 是验收目标。
现场实机条件确认后，还需完成 30 分钟完整待机、1 小时混合运行、至少 10 轮取物递送，
以及真人唤醒、指令理解和播报听感检查。静态相机测试和软件测试不能替代这些结果。
