# X1 本地 Qwen3-VL-4B 适配记录

**本文保留早期厂商包接入历史。当前配置已改为 GenieX + 完整 GGUF，
见 [离线验证和 demo 接入记录](x1-qwen3-vl-4b-official-experiment.md)。**

后续定位见 [4B 识别退化检查](x1-qwen3-vl-4b-diagnosis.md)：同分辨率 GPU
对照、直接 SDK 复现及 DeepStack 特征路径缺失证据。

2026-09-16，按单机端侧要求接入
`qwen3-vl-4b-instruct-448x448-qnn2.40-w4a16-qcs8550`。
这里记录的是 X1 NPU 实测，不能用此前 GPU/GGUF 对照结果代替。

## 运行方式

- 意图、物品定位、抓取视觉判断共用一个本地 4B 服务，端口仍为 18888。
- ACT、Whisper、人员检测保留原来的模型和本地接口，不增加 GPU 回退。
- 使用厂商完整 AIDEM 模型包，不在正式服务中启用 raw 配置或词嵌入拦截实验。
- AidGen SDK / QNN240 后端为 2.4.3.166，AidGenSE 为 3.3.0；服务显式传入 `--qnn_ver 240`，不能依赖新版的默认值 248。
- 4B 图像编码器使用私有目录下的 AidLite SDK / QNN240 2.5.0.284；人员检测、Whisper 继续使用系统 AidLite 2.4.1.278。只修改 VLM 子进程的库搜索路径。
- AidLite 仍会扫描系统插件目录，因此 VLM 子进程还通过 `npu_aidlite_backend.c` 将唯一的 `/usr/local/lib/libaidlite_qnn240.so` 加载路径重定向到私有插件。不修改推理函数，不作用于其他进程。
- 原来的低待机开销配置拦截库须用当前 AidGen 头文件重新编译，旧二进制会出现 ABI 不匹配并崩溃。

机器路径、运行库、模型、SHA256 清单都保存在忽略的 `.xlerobot/npu/vlm/`，
选择通过忽略的 `config/local.yaml` 中 `models.vlm`、`npu.vlm_config`、
`npu.vlm_library_dir`、`npu.manifest` 配置。

## 图像与协议

4B 输入先用双三次插值变为 448×448；提示模型返回 0–1000 归一化坐标，
再映射到相机原图。3B 原有 672×672、双阶段重采样和像素坐标协议保留。
只接受声明的坐标单位，不根据数值猜测单位。单个框多包一层数组的输出可解包，
但仍检查有限值、边界、置信度和完成状态。

运行时请求继续使用非零 temperature=0.1。在当前 QNN240 后端中，
temperature=0 会触发采样器断言并终止服务。

## 本次离线观察

固定使用此前头部图像，未驱动电机。完整包成功加载并完成图文推理。
简短图文请求约 1–3 秒；正式意图提示中的“拿蓝色打火机”“拿羽毛球”
及“不要拿杯子”分别返回取物、取物、取消，约 2–3 秒。

**框选质量仍有问题，尚不能认定优于 3B。** 初步归一化坐标试验中，
蓝色打火机虽返回 found=true，但框偏向右侧；羽毛球框偏下；白色喷雾瓶也有偏框。
直接沿用 3B 的像素坐标提示甚至会收到超过 448 的坐标。
完整厂商包与 raw 包在同组输入上产生相同结果，换包没有消除这些偏差。
因此，本次“完成接入”不等于“通过抓取递送实机验收”。

原始响应与耗时保存在本机 `.xlerobot/npu/qwen3-migration/`。
图文报告为该目录下的 `public-report/index.html`，内嵌头部/腕部图片、
按声明坐标换算的红框、原始输出和耗时，可直接用浏览器打开或另存离线查看。
不同提示词、图像编码和 raw/完整包的结果分组展示，不合并计算准确率。
其中 `smoke-production.json` 是早期像素提示试验，
`intent-production.json` 是正式意图提示试验，`production-client.json` 是接入后客户端检查。
这些机器图像和日志不提交。

接入后的正式客户端再次检查同一张头部图片，羽毛球、蓝色打火机、白色喷雾瓶
均返回空检测，约 1.9–2.0 秒。带输出示例的另一组提示能返回部分框，
但偏框仍然明显，所以没有据此替换正式提示。腕部打火机样本还出现
`grasped=false` 与“被夹爪夹住，悬空于桌面上方”的说明互相矛盾，
置信度为 0.98。该结果原样记录，没有根据理由文本强行改成成功。

四个推理服务联启及本地健康检查已通过；`/proc/PID/maps` 确认 VLM
使用私有 AidLite 2.5，人员检测、Whisper 使用系统 AidLite 2.4。
仅推理服务空闲时的 10 秒整机 CPU 样本为 11.0%；此时 ROS demo 未启动，
**这不是完整 demo 的待机负载**。短样本也不代表长时间稳定性结论。
完成软件检查和构建后停止测试进程，保留 4B 本地配置，暂未恢复实机运动。

## 验证与回退

软件测试覆盖 448 输入、归一化到原图的转换、单框嵌套数组、保留 3B 行为，
以及两种本地配置对远端地址的拒绝。构建从 `ros2_ws` 执行。

升级前的工作区差异、运行库、配置已保存到本机
`.xlerobot/npu/qwen3-migration/`。回退需要同时恢复对应 SDK、服务及配置；
不能在新版服务默认使用 QNN248 时仅把模型名称改回 3B。
停止使用 `tools/run demo --stop`；真实运动启动仍必须显式使用
`tools/run demo --hardware`。不要让失败的任务在重启后自动重跑。
