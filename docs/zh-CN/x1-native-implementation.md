# X1 原生分支第一阶段实现与验证

2026-09-15。源码分支 `x1-native`，原迁移状态保存在
`baseline/x1-pre-refactor`（`bd85c8b`）。该基线未达到性能目标。
机器配置、凭据及配置引用的备份位于忽略目录
`.xlerobot/environment/x1-native-baseline-20260915-094057/`，不提交到仓库。

**验收状态：软件与局部性能验证阶段，尚不能声称整机低于 60%。**
开发期间 demo 服务保持停止，独立相机测试只打开 UVC 摄像头，不启动控制器。

## 已实现的运行路径

- `robot_state_gateway` 集中接收 TF，提供有界的时间戳查询服务。物品定位、人员检测
  不再各自在 Python 中解析整棵 50 Hz TF 树。查询失败明确返回错误，不回退到最新变换。
  保留现有 3 秒 TF 查询预算，接口接受 0–5 秒的显式期限；客户端另留 0.25 秒
  发现/传输预算，不通过偷偷缩短 TF 等待时间来降低负载。
- 网关以 5 Hz 提供最新关节状态摘要，保留采集时间，只发布新样本。任务就绪判断
  仍检查原来的 0.5 秒新鲜度；头部调整和稳定确认阶段才订阅完整关节流。
  摘要不参与 ACT 动作执行。
- ACT 的关节和图像订阅均随动作创建、释放，取消或异常也清空缓存；启动时拒绝
  上一动作的旧数据。人物搜索仅在后退阶段消费里程计，后退前等待新鲜样本。
- X1 网页取消地图、视频、遥控和工程入口，也不创建相关 TF/图像/激光订阅与
  20 Hz 地图定时器。HTTP 层同时拒绝这些入口；保留任务、错误、取消和底盘停止。
  演示取物固定选择 ACT。
- X1 演示不再启动维护姿态服务；网页也不再创建维护姿态和手动导航客户端。
  ACT 前的 MoveIt 避碰准备动作仍走原链路。
- 腕部相机使用 C++ OpenCV/V4L2 路径，保持 MJPG、640×480、30 fps 和原光学坐标系。
  持续取走帧，队列限定一帧；没有图像消费者时仅每秒解码一帧做有效性检查。
  有消费者时发布原有 BGR8 图像。每次重新打开相机先做解码验证。
  相机自己发布 2 Hz 健康信息，独立健康节点不再订阅腕部大图。
- `tools/doctor robot --profile` 增加滚动 10 秒 CPU 结果，包含超标窗口数量。
  CPU 包含系统态和中断，报告不以整场平均掩盖局部过载，也不施加 CPUQuota。

仍沿用原推理部署、权重、动作格式与控制频率：Whisper、人员检测在 X1 CPU，
ACT/VLM 使用原远程服务。固定六条音频和任务期间暂停新指令的既有实现保留。
本阶段没有修改内核、DDS、控制频率、碰撞监测、定位门槛或 MoveIt 避碰规划。

## TF 局部对照

在隔离 ROS 域，以 19 个变换、50 Hz 持续回放；旧版直接运行保存基线中的两个节点，
新版运行同样两个节点及 C++ 网关。各预热 8 秒后测三轮，每轮至少 60 秒。
不发布相机图像、不调用推理、不启动硬件控制器。

| 路径 | 物品节点，单核 % | 人员节点，单核 % | 网关，单核 % | 合计，单核 % |
| --- | ---: | ---: | ---: | ---: |
| 保存基线 | 78.448 | 77.632 | — | 156.081 |
| X1 新版 | 0.056 | 0.056 | 2.026 | 2.137 |

上述是三个进程的 CPU 对照，不是整机负载；回放发布器不计入两边合计。
六核整机不能直接减去 153.94 个百分点，也不能从历史 81.55% 推算新 demo 的最终成绩。
开发主机同时有少量编辑、编译和软件测试活动，因此保留每轮数据供复查，整机验收时
还需在无开发负载的同工况重复。原始数据及复现脚本位于忽略目录
`.xlerobot/environment/x1-under60-dev/`。

## 腕部相机局部对照

同一 UVC 设备、MJPG、640×480、配置 30 fps，两个版本各测三轮至少 60 秒待机，
无人订阅原始图像。随后各进行三次重新订阅，每次约 5 秒，检查尺寸、BGR8 编码、
光学坐标系、动作时间屏障和图像年龄。相机测试期间没有启动电机或其他 demo 节点。

| 路径 | 待机单核 CPU 三轮 % | 平均单核 % | 首张新鲜图像 ms | 5 秒收到帧数 | 最大图像年龄 ms |
| --- | --- | ---: | --- | --- | ---: |
| 原 Python 驱动 | 43.324 / 41.618 / 41.828 | 42.257 | 260 / 47 / 70 | 96 / 141 / 143 | 58.6 |
| 新 C++ 驱动 | 1.116 / 1.099 / 1.115 | 1.110 | 83 / 57 / 64 | 142 / 138 / 140 | 51.3 |

新路径在独立测试中交付约 28 fps，不能把配置的 30 fps 直接当成交付帧率。
旧路径首轮有明显波动，后两轮接近新版；本轮没有证明运动期间图像时序和抓取效果。
测试脚本中曾误将 Humble 返回的诊断 `byte` 与整数比较，已修正并重新完成原生版
三轮测量；旧版首次取帧的预设帧数断言也已改为记录实测吞吐与实际新鲜度约束。
保留这些测试修正记录，避免把脚本断言失败误报成相机故障。

## 验证与后续门槛

已验证：时间戳插值、无效时间戳/超时错误、旧关节样本不被刷新、网页无图像/TF端点、
按需资源释放、固定提示的终态处理、ACT 软件执行中的完成/补帧/夹爪闭合输出及取消。
这些软件测试不打开电机；软件中的闭合输出检查不能替代实机夹持成功。

相关 C++/Python 包与网页已构建、安装。以上表格均为进程级测量，不是完整 demo 验收。
一次跨多个 ROS 包的大进程测试出现底层 `Bus error`；按包隔离执行后对应测试通过。
尚未证明该底层错误的原因，后续稳定性测试必须继续观察，不能忽略。

下一门槛是有人看护、活动范围清空后的整机启动与待机采样，再测语音、导航、抓取、
寻人递送和取消各阶段。30 分钟待机、1 小时混合任务、至少 10 轮实机任务尚未完成。
Nav2 组件组合、D455 生产者健康诊断、ACT 仅对实际请求帧编解码和单一视觉工作进程
尚未实现，不把这些预期收益计入本阶段成绩。NPU 工作继续留到后续专题。

## 部署和回退

当前忽略的 `config/local.yaml` 已启用 X1 低负载配置；源码修改后须从 `ros2_ws`
构建 interfaces、perception、policy、task、bringup、hmi，并构建/安装 HMI 网页资源。
真实运动仍只通过 `tools/run demo --hardware`，停止用 `tools/run demo --stop`。

回退前先停止服务、保存后续修改，再切回 `baseline/x1-pre-refactor` 并重新构建该版本。
禁止把旧分支源码与新分支 build/install 混用。机器配置需要时从上述私有备份恢复。
不要通过关闭碰撞检查或降低控制频率使性能报表看起来达标。
