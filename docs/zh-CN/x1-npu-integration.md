## 演示阶段的执行范围（用户调整后）

以已经能运行的 Qwen2.5-VL-3B 为主。尝试 4B 是为了改善抓取判断的误报，
不是迁移的必选项；用户明确以演示效果为准后，暂停 4B 探索和长时间压力测试。
后续只做接口、基本识别、速度和动作数组的短验证，优先接通可演示的流程。
抓取判断误报仍作为已知问题记录，不能把“模型能运行”写成“完整任务已成功”。

## 实现范围

增加 `tools/run npu`：前台管理本机 VLM、ACT、人员检测、ASR 四个推理进程。
`tools/run npu --status` 查看进程，`tools/run npu --stop` 停止整组。
该入口禁止 `--hardware`，不启动 ROS、相机、麦克风或电机，不修改 demo 服务地址。

`services/npu/server.py` 提供有界、串行的回环 HTTP 接口：

- ACT：独立 Python 3.12 / ORT QNN，保留实际权重的 `[1,3,480,640]` 腕部输入、
  六维状态、完整 `[1,100,6]` 物理动作输出及归一化。禁止 CPU 回退。
- 人员检测：AidLite QNN236，沿用已验证的 YOLOv8n 输入布局和后处理。
- ASR：AidLite QNN240 Whisper-base，16 kHz 单声道浮点输入，逐段清空缓存，
  返回完成状态、无语音概率、语言概率和平均 token 对数概率。
- 本地请求携带同机单调时钟截止时间，过期请求不推理，过期结果不返回动作。
  限制请求大小、图像尺寸、音频长度与输出形状；接口只返回数据。

新增 ROS 侧 `NpuPersonDetector`、`NpuTranscriber`，通过显式参数选择本地后端。
ACT 复用已有 HTTP 客户端，为回环请求增加截止时间。原来的关节约束、动作队列、
定位与碰撞检查保持原逻辑。ASR 服务失败时播报固定未理解提示，禁止发出任务。

机器配置的 `demo.asr_backend`、`demo.person_backend` 缺省仍为 `cpu`；选择 `npu`
时必须先启动对应本地工作进程。ACT 候选接口为回环 18901 端口。
本轮不会因推理接口成功就自动启用实际机器人任务。

## 重要发现与修复

### 1. NPU 模型也可能长期消耗 CPU

默认 AidGen QNN240 的三个后台线程在无请求时合计消耗约一个 CPU 核。
5 秒线程采样各约 33.4%；GDB 堆栈落在 AidGen 内部线程池的锁操作。
SDK `Context::get_config()` 显示 `generator_n-threads=3`、`generator_cpu-mask=0xe0`。
本机在线 CPU 为 0–5，默认掩码只与在线 CPU 5 相交。

通过公开 `Context::set_config("generator_n-threads", "0")` 在创建 Generator 前
关闭这组线程，SDK 返回成功，模型仍能处理图文请求，5 秒初测待机 CPU 接近零。
供应商 HTTP 程序未直接暴露此参数，使用仅注入该进程的
`tools/lib/npu_aidgen_config.cpp` 调用公开 API；不修改 SDK 二进制、系统库或控制线程。
`npu.low_idle_cpu=false` 可在实验中回退到供应商默认线程设置。

虽然进程加载了 libgomp，本次堆栈证据指向 AidGen 自己的线程池，不能把
`OMP_WAIT_POLICY` 当作已经验证的修复。

### 2. 零温度会使本机采样器退出

首次四模型混合试验的 VLM 因 `temperature=0` 触发
`sampler-utils.hpp: temp > 0.f` 断言并退出。其他工作进程当时仍存活。
这次失败不能解释为 NPU 内存不足或模型互不兼容。
实验请求改为已验证的 `0.1`；未来本地 VLM 适配必须显式处理这一差异。

### 3. 需要验证整个接口，而不只是模型计算

ACT 独立环境起初缺少 Pillow，模型加载与 tensor 推理成功，HTTP 图片请求失败。
补充并固定解码依赖，启动时检查导入；之后同一协议可以返回完整动作块。
独立环境依赖见 `services/npu/requirements-act.txt`，不能装进 ROS Python 3.10 环境。

ASR 语言置信度从起始 token 的语言 logits 计算，不能因为强制中文就伪造为 1。
人员框检查使用原始图像尺寸，拒绝非有限坐标、越界框与非法置信度。

冷启动后的第一条 ASR 请求曾因特征提取器初始化耗时约 2.7 秒，热请求约 0.18 秒。
最终工作进程在发布健康状态前用一秒静音完成预热，不把这部分耗时藏在用户首条
指令中。预热仍消耗启动时间，并没有减少这部分计算。

### 4. Qwen3-VL-4B：完成加载不等于支持推理

现有原始 QNN240 4B 模型包有三段 LLM、ViT、词向量和位置编码文件。
隔离实验分离原始 Genie 配置与供应商 HTTP 视觉配置，修正视觉 patch 尺寸为 16，
与[Qwen 官方配置](https://huggingface.co/Qwen/Qwen3-VL-4B-Instruct/raw/main/config.json)
一致。随后可加载 LLM 与视觉编码器，但第一条实际请求仍失败。

底层日志明确报告：收到 embedding 输入，但该配置被识别为 text-only 模型；之后
出现 T2E 溢出、乱码输出和上下文耗尽。客户端首次超时后的 429 是连带失败，
不能把这一批 HTTP 错误当成 72 次有效质量测试，更不能据此比较 3B 与 4B 的能力。

`npu_aidgen_raw_embedding.cpp` 仅保留为此次失败实验的复现材料，使用的是特定
AidGenSE 版本的导出桥接符号，**不是公开稳定 API**，也没有接入受管理的工作进程。
这与已验证的公开 Context 线程配置修复不同。没有升级系统 SDK 或改写供应商库；
后续应先解决原始多模态包与运行时的匹配问题，不能继续用“能加载”作为通过依据。

## 判断质量：不能以“HTTP 成功”验收

固定 16 条指令和 8 个腕部图文请求，每项重复三次。图文请求使用四张既有录像帧，
分别询问黄色圆筒和羽毛球；其中一张只凭单帧无法确认是否已经抬升，保留为未标注。
因此负样本为七个不同请求、21 次重复，未标注的三次不算正确率分母，也不算正样本。

初始本地 Qwen2.5-VL-3B 使用原生产提示：部分否定指令被接受，抓取判断明显误报。
移除直接给出答案的 JSON 模板、明确拒识类别后，初轮 16 条指令的任务接受/拒绝
检查全部通过；复查还发现 `source_place=桌面` 虽可被解析却不是地图标识 `table`，
因此继续补地点字段检查，不能只凭物品名和是否接受宣称协议完全正确。

视觉判断的候选提示仍不能通过。按当前生产视觉成功阈值 0.70，初始提示与候选
提示都在这 21 次负样本中产生 15 次视觉误接受。布尔输出、置信度门槛和实际任务
结果是不同统计层次，原始 JSON 均保留。

同一测试集也显式请求现有 GPU 模型作参考，不把参考模型输出当作真值。
原提示存在把否定/闲聊变为取物，以及照抄抓取示例中置信度 0.0 的问题；候选提示
改善意图，但仍有把错物或接触未夹持判为成功的情况。

GPU 候选提示在此小集合的意图协议检查为 48/48，但抓取负样本仍有 6/21 次超过
0.70 的视觉误接受；本地 3B 为 15/21。原 GPU 提示虽然没有超过阈值的误接受，
却在回答中照抄 0.0 置信度，且没有已确认正样本，不能说原方案更可靠。
这些样本参与过提示调整，不能当成独立泛化测试。

现有控制代码还会结合夹爪开度处理视觉结果；因此这里的“视觉误接受”不等于
机器人一定实际误递送。本轮没有修改机械判据来提高通过率，也没有执行真实抓取。

## 初步混合结果的口径

四模型驻留，保存的语音、文字、图像和 ACT 观察按任务阶段交替请求。
关闭 AidGen 后台线程后的 60 秒冒烟试验无接口错误：ACT 平均约 37 ms，人员检测
约 43 ms，ASR 约 183 ms，意图约 2.22 秒，视觉约 3.47 秒。
该 ACT 样本与原策略参考的最大绝对差约 0.000955。

这些时间包含 HTTP 往返、解码和相应推理；测试客户端提前准备了编码输入，不包含
真实相机等待或每次 ROS 客户端编码。该轮整机 CPU 约 28.1%，**没有运行导航或
完整 demo**，不能据此宣称完整 demo 低于 60%。测试期间有开发活动，也不能将
它当作最终受控性能基准。

## 脱网、驻留与接口回放

使用临时 systemd 服务给推理进程及其子进程配置 `IPAddressDeny=any`，只允许
localhost。系统的连接探针对照证明：普通进程可以连接现有 GPU ACT 服务，相同
网络限制下的进程被拒绝。四模型在该限制下重新加载并通过三轮混合测试。
系统其他进程的网络、路由与 SSH 均未改动。

| 脱网混合轮次 | 实际时长 | 整机平均 CPU | 最高 10 秒窗口 CPU | 接口错误 |
| --- | ---: | ---: | ---: | ---: |
| 1 | 60.24 秒 | 28.89% | 32.73% | 0 |
| 2 | 62.01 秒 | 28.36% | 30.10% | 0 |
| 3 | 62.07 秒 | 30.16% | 36.68% | 0 |

每轮 ACT 平均约 32–33 ms，人员检测约 43–45 ms，意图约 2.2 秒，视觉约 3.5 秒。
第一轮 ASR 包含冷预处理，后两轮平均 182–184 ms。工作进程禁止 CPU 模型回退；
CPU 仍负责解码、特征提取与服务调度。这不是“所有计算都在 NPU”。

已有 30 分钟四模型驻留待机完成，实际 1800.44 秒：各进程首末 RSS 差为 0 KiB，
最小整机可用内存约 6.90 GiB。整机平均 CPU 11.22%、最高 10 秒窗口 31.07%；
期间有构建和测试活动，且没有启动 ROS 导航。此轮 ASR 尚未运行特征提取器，
其 RSS 约 78 MiB，不能与首次识别后的约 344 MiB 直接比较并判作泄漏。

原定一小时的固定输入混合测试按用户要求在约 30.4 分钟时提前结束，期间接口
错误为 0。整机平均 CPU 约 34.47%，包含额外样本准备、构建和模型包下载活动，
不作为受控性能基准。结果保存为 `offline-mixed-interrupted.json`，不标记一小时
验收通过。615 个录像观察的 CPU 参考已准备好，但没有执行完整 NPU 轨迹回放；
这项长验证也不再作为当前演示接入的前置条件。

实际 ROS Python 客户端只读回放：ASR 识别出羽毛球指令，语言概率约 0.9988，
静音返回空文本；人员客户端返回三个人框；原 ACT 客户端收到有限的 100×6 动作。
本地 ACT 请求包含编码在内的截止时间，客户端也独立丢弃过期响应。

本机已有 SDK 授权，允许 localhost 也允许访问本地 SDK 守护进程。这里证明的是
**推理进程禁止远程访问时可重新启动和推理**；尚未证明整机断电、完全断网后的
授权启动链，也没有声称脱离模型准备/训练环境。

## 复现与回退

在忽略的 `config/local.yaml` 配置 `npu.act_model`、`npu.person_model`、
`npu.whisper_model`、`npu.vlm_config`、`npu.manifest`；manifest 保存本地模型文件
的 SHA256。启动按顺序加载模型并等待健康接口；失败时清理整组进程，不自动重启。
QNN 设备发现兼容链接的说明见[上一轮实验](x1-npu-vlm-act-experiments.md)。
新增 `tools/setup robot --install-npu-device-rule`，仅针对本机已有的 secure FastRPC
字符设备安装 udev 别名规则。规则不设置 OWNER、GROUP 或 MODE；发现同名的其他
设备时拒绝覆盖。它不安装模型、不启动服务，也不启用任何机器人任务。
该安装入口已有软件检查，本轮结束时尚未安装系统规则，现有实验使用临时别名；
因此不能声称已验证重启后的设备发现。

```bash
# X1 首次准备设备发现别名（需要 sudo；不打开设备）：
tools/setup robot --install-npu-device-rule
tools/run npu
# 在另一终端检查或停止：
tools/run npu --status
tools/run npu --stop

tools/doctor robot --npu-system-probe --help
tools/doctor robot --npu-vlm-probe --help
```

`--reference-config config/local.yaml` 是 VLM 探针的显式远程参考模式，仅用于保存
输入的质量对照；缺省仍只允许回环模型地址。所有探针都不发 ROS 任务。

原始结果位于 `.xlerobot/npu/integration/`，受控工作进程记录位于
`.xlerobot/npu/stack/`。现有配置备份为 `local-before-npu.yaml`，新增机器参数未提交。
后续演示接入以必要的短验证为主，长时间稳定性测试后置；真实运动仍需显式
`--hardware` 和现场条件，本轮没有执行。

软件验证：四个相关 ROS 包构建成功；语音 39 项、人员感知 55 项、策略 36 项和
bringup 中 NPU 相关 25 项软件测试通过。NPU 测试覆盖过期结果丢弃、假服务协议、
启动前取消、设备安装参数边界、ASR 预热以及 SDK 配置桥接；测试不加载真实模型
或打开电机。此前一项人员预热测试依赖工作目录下存在模型文件，已改用临时假文件，
使其在 colcon 的构建目录中也能运行。
