# 标定之后：底盘、雷达、桌面对齐与参数替换

本文是复现说明，不代表底盘、雷达或抓取对齐已在当前版本完成实机验收。
本轮不再要求这些实验；同一台未改装的机器人可以保留原参数，明确记录来源。
不要用示例数值替代另一台机器的测量，也不要为了通过流程伪造“零误差”。

## 底盘几何：先轮径，再轮距

适用于参考双轮差速底盘。有效轮径决定行走尺度，有效轮距决定旋转尺度；
轮胎受载、地面摩擦和打滑都会影响结果，不只是用尺量一下零件尺寸。

准备平整防滑地面、卷尺、地面胶带、直角尺。保持实际使用时的负载和胎面状态。
沿机器人 `base_link` 前向做标记，测量同一个底盘参考点的位置，不能拿里程计自身作为真值。
运行试验前停止 Demo/导航，只允许一个底盘控制入口。已有底盘采集网页只是表单，
不会自动跑以下轨迹；需人工监督操作。若不做试验，保留旧参数，不填“验证通过”。

1. **直行轮径**：在地面标出起点和方向，低速行走约 1～2 m；记录命令距离和卷尺实测距离。
   前后向各重复几次（表单中填写正的距离大小）。明显走弯、打滑或碰障碍的试验应重做。
   `新轮径 = 旧轮径 × 平均(实际距离 / 命令距离)`。
2. **旋转轮距**：先使用修正后的轮径，再低速左右旋转，记录实际转角。
   可转一圈再测相对起始线的欠转/过转量；填写完整角度，不是取模后的余角。
   `新轮距 = 旧轮距 × 平均(命令角度 / 实际角度)`。
   不要把旧轮径下的旋转记录混入这一轮；当前求解器按这两个顺序阶段解释输入。
3. **留出复测**：使用未参与计算的距离和转角，报告实际误差和重复性。
   左右旋转误差不对称或直行明显偏航，先查机械、左右轮差异和地面，不用一个轮距补偿掩盖。

填写 [测量模板](../../examples/calibration/base_measurements.yaml)，其中数字仅为格式演示：

```bash
./tools/calibrate base --measurements /path/to/my-base-measurements.yaml
```

输出保存为本机 `draft/components/base_geometry.yaml`。完整新机标定使用
`activate`、`render`；同机复用现有整套运行参数见后面的版本替换说明。

## 雷达角度对齐：校正安装 yaw，不是旋转地图

先检查雷达固定牢靠、扫描面水平、线缆不拉扯。参考机雷达为倒置安装：
`geometry.yaml` 的 `sensors.lidar_roll` 为 π，`lidar_yaw_deg` 为水平安装角（度），
`lidar_xyz` 为安装平移（米）。角度符号以 URDF 为准：绕底盘向上的 Z 轴逆时针为正。
不要同时在雷达驱动和 TF 中做相同的翻转/偏转；本工具不标定 roll、pitch 或平移。

### 直墙参考法

1. 将底盘正前方独立对准一面平直墙。用墙到左右两个底盘基准点的距离相等来确认，
   不要依靠雷达画面把机器人“对正”，否则无法区分底盘摆歪和雷达装歪。
2. 机器人静止，选取同一面墙、跨度至少 0.5 m 的连续扫描点，排除桌腿、人、玻璃和墙角。
3. 将点保存为带 `x,y` 表头的 CSV，单位米，必须是**原始 LaserScan 的 frame 坐标**：
   `x=r*cos(angle_min+i*angle_increment)`，`y=r*sin(...)`，过滤非有限或越界量程。
   不要先变换到 base_link 后再传入，避免重复应用安装角。
4. 运行离线参考工具（只读文件、不连接设备、不修改配置）：

```bash
./tools/calibrate lidar-yaw --points /path/to/wall-scan.csv \
  --current-yaw-deg 186.442 --roll-deg 180 --wall-normal-deg 0
```

`186.442` 只是参考配置，换成当前使用的值。墙在底盘正前方且确实摆正时，墙法线取 0°。
工具先处理倒置，再拟合直线法线，给出候选 yaw、修正量、拟合 RMS 和墙面跨度。
点数不足 20、跨度不足、拟合 RMS 大于 10 mm、修正超过 15°都会拒绝；
这些只是输入检查，不代表精度证书。不要把单次墙面倾斜直接当成安装误差。
换另一个距离及另一面墙重复验证；若结果随位置变化，检查摆位和测量方法。

### 保存与应用

不要直接改 `units/<unit>/runtime/geometry.yaml`，它有校验和且会被重新生成覆盖。
停止使用标定配置的运行程序，将当前 runtime 的五个配置文件复制到本机临时目录，
只修改其中 `geometry.yaml` 的 `sensors.lidar_yaw_deg`，在 `transforms.yaml.provenance`
记录测量方式和原版本，再用 `tools/calibrate import-runtime --input PATH --version VERSION`
保存完整同机快照。该命令会选择并渲染新版本；重启运行程序后 TF 才会变化。
改动后用墙面和少量低速运动检查扫描与地图是否重合；不靠重新建图掩盖固定角偏。
本次不会替你执行上述实机试验或改雷达数值。

## 手眼精度：Tag 23 悬停在桌面板上方

这是可行的**桌面视觉对齐验证**，不是夹爪尖端绝对精度测量。
被对齐的是 Tag 23 的中心；Tag 到夹爪的偏移由手眼求解的 `jaw_from_tag` 提供。
现有[统一工作台](calibration-workbench.md)用桌面板坐标中的已知点 `(x,y)` 和高度 `h` 定义期望 Tag 位姿，
通过 `base_from_board × board_from_tag_goal × inverse(jaw_from_tag)` 求夹爪目标。
必须同时约束 Tag 朝向；只指定中心位置不足以确定夹爪目标位姿。

当前自动流程固定为板中心及 X ±30 mm 三点，Tag 中心在板面上方 200 mm，不贴板、不碰触；
沿路径检查夹爪、腕部相机和机械臂包络，至少保留 50 mm 桌面间隙。两种高度不要混淆。
报告板坐标中的位置偏差和关节到位偏差，三点完成后给出未应用的总偏移建议。
每点 20 帧不是 20 次重复到位；重复性及补偿后的精度仍需另外验证。
悬停高度应通过尺子或侧视参考抽查，不能只看正面图像中两个中心是否重合。

### 遮挡处理

- 桌面板由多个已知相对位置的 Tag 组成，不需要看到被对齐的那个中心点。
  可先完整识别板，再用仍可见、分布充分的其他 Tag 估计整板姿态，推算被挡住的点。
- 建议板放得比夹爪投影更宽，让周边至少三个分布不近共线的 Tag 保持可见；
  同时 Tag 23 必须可见，头部与底盘保持固定。
- 若板被完全挡住，当前验证会等待新鲜的合格观测，超时则失败，不使用冻结参考冒充测量。
  板移动后必须重新定位和规划。
- 悬停工具已支持部分板识别与自动三点验证；头相机标定仍要求完整 16 Tag，不降低采样要求。

这种方法可以验证“相机看到的板”和“Tag 实际到位”的一致性，但共享相机和模型会带来相关误差。
如果要宣称夹爪尖端的毫米级绝对精度，还需独立的物理参考；不要把板/Tag 残差等同于尖端误差。

## 抓取对齐：可选，不要求继续做实验

手眼标定之后，可先使用原有补偿进行受控抓取观察。
本轮跳过新的抓取对齐实验，保留原参数并记录“未重新验证”；这与证明新补偿有效是两回事。
不要直接把旧补偿清零，也不要从手眼残差自动推导出重力下垂。

如果以后要做：先测多个桌面点的实际落点，再判断是否存在一致偏差。
满足任务精度即可记录无需额外补偿；只有稳定的同向偏差才考虑固定补偿。
随姿态明显变化的偏差应查机械/FK/深度原因。单独测得重力下垂才单独补偿，避免重复计入。
现有 [YAML 测量模板](../../examples/calibration/grasp_alignment_measurements.yaml)和求解器保留为可选工具，
不新增本轮强制验收项目。全新机器人仍需提供有来源的完整配置，不能借同机替换功能自动套用别人的参数。

## 简单替换和恢复标定

适用于已有完整 active 标定的**同一台机器人**。先停止 Demo/数采等运行程序；
参数切换本身不驱动硬件，也不会热更新已启动的节点。

```bash
./tools/calibrate status
# 记下 active 的旧版本 ID。先看替换清单，不写入：
./tools/calibrate replace --version my-calibration-v2 \
  --components servo head-camera right-handeye --dry-run
# 替换、版本化并生成 runtime：
./tools/calibrate replace --version my-calibration-v2 \
  --components servo head-camera right-handeye
./tools/calibrate status
# 需要恢复时，一步选择并渲染旧版本：
./tools/calibrate switch --version OLD_VERSION_ID
```

每次使用唯一的新版本 ID；已存在的版本不会覆盖。保留项包括底盘、雷达安装参数和旧抓取补偿，
它们不会被写成“本轮测量通过”。新旧组件混合后的抓取效果仍需实机判断。
前序舵机/头相机变化后，后续标定应基于相同前序重采，不能混搭不兼容的草稿。
完整新机标定仍走原有 `activate` 流程；`switch` 也可用于完整版本的恢复。

实际应用关系：`servo` 更新舵机解码参数；`head-camera` 更新头部相机安装外参；
`right-handeye` 的 `y` 更新夹爪 Tag 23 安装位姿，`x` 保存在证据中，
**不会直接覆盖相机 TF，也不会自动生成新的抓取补偿**。
重启 Demo/数采后才加载所选 runtime；模型权重和数据集不会随标定版本自动改变。
