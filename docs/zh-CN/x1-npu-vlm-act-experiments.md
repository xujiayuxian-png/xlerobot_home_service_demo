# X1：同一个 VLM 做框选和意图识别，ACT 在 NPU 上推理

日期：2026-09-15；基于 `x1-native` / `27d6d75`。
这是[第一轮 NPU 探索](x1-npu-experiments.md)的后续实验，未迁移生产后端。

## 1. 本轮结论

- **同一个 Qwen2.5-VL-3B 已在 X1 上完成物品框选和意图解析。** 使用同一进程、
  同一模型 ID 和权重，按请求选择图文输入或纯文本输入，没有再加载独立意图 LLM。
  仍有框不够准、歧义指令分类错误和输出格式不一致，不能宣称开放场景已通过验收。
- **当前实际 ACT 权重已在 X1 NPU 上运行完整 100 步动作块。** 不是随机初始化
  网络、替代模型或仅运行 ResNet，也不是 CPU 回退。包含输入归一化和动作反归一化。
- demo 全程停止，没有打开电机、发送 ROS 动作或向机器人回放输出。GPU 主机只用于
  读取权重/已有数据、导出与浮点参考验证，现有 ACT 服务及配置未切换。

## 2. VLM：模型与试验方法

使用已有模型包 `qwen2.5-vl-3b-instruct-672x672-qnn2.36-w4a16-qcs8550`，
W4A16、672×672、上下文 2048；由本机 AidGenSE / AidGen 加载。
模型包标记 QNN2.36，服务器自动选择本机 QNN2.40 后端；加载日志确认视觉编码器
和生成模型初始化成功。本轮没有继续为 Qwen3-VL-4B 更换整套 SDK。

模型服务器使用独立实验配置和 18888 端口。供应商服务器日志虽然写 `0.0.0.0`，
实际通过仅在实验进程生效的 `LD_PRELOAD` bind 包装限制到 `127.0.0.1`，
以 `ss` 检查真实监听地址；实验结束停止进程。包装不修改供应商二进制、系统库
或防火墙，也不拦截模型访问本机 SDK 所需的出站连接。

### 意图：10 个不同指令，各重复三次

包括羽毛球、透明水杯、红色螺丝刀、鼠标、纸巾、小药盒，以及取消、否定取消、
闲聊和“把那个东西给我”。框选与纯文本请求交替使用同一个模型服务，避免只验证
一个刚启动、没有处理过图像的独立语言模型。

结果 **27/30 通过**，即 9 个不同指令各三次正确；失败均为“把那个东西给我”
被分类为 `unknown`，预期是 `clarify`。两者都不应触发取物，但交互语义不相同。
增加指代不清的说明后这一问题仍存在，保留失败记录，没有改预期答案使测试通过。
平均 HTTP 往返耗时约 **0.658 秒**。

模型能保留不同物品名称、颜色限定，接受任务、取消和否定取消的这些样本均正确。
测试数量小且模板经过调试，不能外推成真实开放指令的 90% 准确率。
初期直接给 Qwen2.5-VL 拼接 Qwen3 的 `<think>` 前缀效果差；改用对应模型的
标准 ChatML 模板和明确任务说明后，语言输出恢复正常。

### 框选：9 个不同图文请求，各重复三次

输入包括供应商的海滩/食材图，以及既有抓取数据中的两张腕部图。人工在原图上
给出近似参考框，先固定这些参考框再检查结果；参考框不是专业标注数据集。
正样本标准为 `found=true`、有效 xyxy 框、IoU ≥0.5；负样本要求明确返回
`found=false, box=null`。所有坐标转换均显式记录。

第一次要求模型直接输出 0..1000 归一化坐标，模型没有稳定遵守，正样本全部未通过。
后续明确把输入缩放到 **672×672**，要求输出该图的像素坐标，再由程序映射回原图。
这是一次新的协议试验，第一轮失败报告保留，不事后把旧输出改口径算作通过。

| 请求 | 代表性 IoU | 三次结果 |
| --- | ---: | --- |
| 狗 | 0.586 | 通过 |
| 人 | 0.544 | IoU 粗筛通过，但明显漏掉头部 |
| 生姜 | 0.940 | 通过 |
| 左侧三文鱼 | 0.642 | 通过 |
| 腕部图：黄色圆筒，接近前 | 0.900 | 通过 |
| 腕部图：黄色圆筒，夹爪附近 | 0.633 | 通过 |
| 食材图中不存在的羽毛球 | — | 通过，明确未找到 |
| 腕部图中不存在的羽毛球 | — | 通过，明确未找到 |
| 海滩图中不存在的水杯 | — | 语义为未找到，但输出 `box=[]`，按严格协议判失败 |

复查参考框后合计 **24/27 协议与 IoU 粗筛通过**，即 8/9 个不同请求各三次；
平均 HTTP 往返约 **2.44 秒**。原始初判为 21/27：绘制对照图时发现人员参考框
漏包含伸出的腿，将左边界从 519 更正为 440 后，使用同一保存输出重算 IoU。
原始标注、初判和更正记录均保留；派生的 `qwen25-reviewed.json` 不是新一轮推理。
`box=[]` 可以在未来接入层明确归一化处理，但本轮没有静默放宽判定。
人员框虽然 IoU 粗筛通过，仍漏掉头部；夹爪附近的圆筒也只框住一部分。
因此不能把这个通过率当成完整框选成功率。对照图位于忽略目录
`.xlerobot/npu/vlm/box-check.png`，蓝色为近似参考，橙色为模型输出。

这些结果支持继续探索“一个 VLM 同时承担框选和意图”的方案。不能据此保证任意
物体、遮挡、细小目标、抓取成功判断或开放复合指令都能可靠完成。

## 3. ACT：真实权重、完整输入输出与一致性

从当前 GPU 服务进程核对并取回 `xlerobot-act-local-grasp-v1`：

- 权重约 198 MiB，ResNet18 + Transformer，腕部 RGB `[1,3,480,640]`。
- 关节观察 `[1,6]`，动作块 `[1,100,6]`，没有增加头部相机输入。
- 保留 checkpoint 的视觉/关节均值、标准差和动作反归一化参数。
- 权重 SHA256：`e667f36bedb7039c1a04acc782b105447336406273b3c762ce701b97f120378d`。

导出时只做推理等价整理：将视觉特征逐项拆开再 stack 的流程改为一次 concat；
固定位置编码和推理阶段全零 latent 预计算。训练专用 VAE 不进入推理图。
没有降低图像分辨率、改动作维度、改 chunk 长度或替换训练权重。

验证使用三个合成观察，以及既有录像的四组 RGB/关节观察。录像来自已有数据集，
并非这次新采集；不是独立于训练数据的泛化测试，更不是机器人真实执行结果。

| 比较 | 最大绝对差 |
| --- | ---: |
| 原策略 + 原预/后处理，与导出包装的 PyTorch 输出 | 七个观察均为 0 |
| 导出机 CPU ONNX / ORT 1.23.2，与 PyTorch 浮点参考 | 约 1.91×10⁻⁶ |
| X1 CPU ONNX / ORT 1.27.0，与同一浮点参考 | 约 3.64×10⁻⁶ |
| NPU HTP FP16，与同一浮点参考 | 初次七样本最大约 0.001675 |

NPU 初次四组真实观察最大差约 0.000955 / 0.001295 / 0.000949 / 0.001514。
误差单位沿用 checkpoint 的物理动作单位，分别记录各关节，不能把夹爪坐标也统一
描述为角度。数值接近支持继续试验，但这些误差仍需结合控制阈值、夹爪闭合边界和
完整动作轨迹验证；本轮不设未经实机验证的“安全误差”结论。

ONNX 图约 132 MiB、320 个节点，SHA256：
`2c9ec0867568821f0b40cf3d6baa708ef8633e37c930fe53fa01d2b8287d874d`。
实际图算子包括 Conv、MatMul、Softmax、LayerNormalization 等。

## 4. ACT：运行环境与性能口径

另建忽略目录中的 Python 3.12 实验环境，安装 ONNX Runtime `1.27.0`、
Qualcomm QNN EP `2.6.0`、ONNX `1.19.0`。不更新 demo 的 Python 3.10 venv、
AidLite、AidGen 或系统 QNN。模型在本机通过 QNN 编译/运行，未上传到第三方转换服务。
这个 Python 3.12 环境不能直接替换 ROS/demo 的 Python 3.10；未来接入需明确选择
独立推理进程或兼容绑定，并重新测量传输成本，本轮没有把新包安装进 demo venv。

QNN 插件起初没有发现 NPU。检查其公开源码后确认：Linux arm64 的设备枚举识别
`/dev/fastrpc-cdsp*`，这台 X1 暴露的是旧名称 `/dev/adsprpc-smd-secure`。
实验临时增加指向真实设备的兼容符号链接；没有伪造模型执行或改设备驱动。
必须进一步成功创建 HTP 会话、完成推理并检查性能日志，不能以“枚举到 NPU”
作为推理成功。本轮测量完成后删除这个临时链接，不做开机持久化。

ACT 指定 HTP V73 / SoC 603、FP16、burst 模式；显式设置
`session.disable_cpu_ep_fallback=1`。七样本预热的 ORT profile 中执行后端只有
`QNNExecutionProvider`，进程实际加载 `libQnnHtp.so`、V73 stub 和 `libcdsprpc.so`。
编译、预热之后停止详细 profile，再统计稳态，避免把逐节点分析开销算进对照。

首次加载/编译约 15 秒，首次完整动作块约 20 ms，预热后初测约 15 ms。
这些是 tensor 输入至物理动作块输出的时间，包括归一化，不包括相机采集、JPEG
解码、网络传输、机器人控制、图像等待或任务管理。不能直接当成整机延迟。

正式对照在 demo 和 VLM 服务均停止时，NPU/CPU 交替，各三轮 60 秒、请求 3 Hz，
循环使用相同七组观察；CPU 为 X1 上的 ONNX FP32、2 个计算线程。
CPU 百分比为进程用户态+内核态 CPU 时间/墙钟时间，100% 表示一个核，不是整机。

| 指标 | X1 CPU FP32 | X1 NPU HTP FP16 |
| --- | ---: | ---: |
| 三轮平均动作块时延 | 395.28 ms | 14.99 ms |
| 三轮各自 p95 范围 | 397.67–399.14 ms | 15.37–15.41 ms |
| 三轮进程 CPU，单核 % | 198.710 / 198.735 / 198.619 | 3.566 / 3.555 / 3.560 |
| 平均实际推理频率 | 2.529 Hz | 3.000 Hz |
| 每轮加载/编译平均时间 | 0.451 s | 14.331 s |
| 峰值进程 RSS 范围 | 298–326 MiB | 541–570 MiB |

每次都输出完整 `[1,100,6]`。NPU 三轮七样本的最大绝对差均为 0.0016746521，
预热 profile 均只包含 QNN 执行；CPU 对照最大差为 0.0000036359。
这里没有测试模型缓存导出，NPU 每轮都重新编译，不把编译代价隐藏为“无加载成本”。

CPU 版单次耗时超过 1/3 秒，实际上无法达到请求的 3 Hz；报告同时保留实际频率，
不将此对照描述为两边都维持 3 Hz。NPU 的收益包括更低延迟和更少 CPU 开销，
但 HTP 编译与运行占用的进程峰值内存可能高于 CPU 版，不能只比较速度。

## 5. 复现、边界与后续

公共入口仍为 `tools/doctor`：

```bash
tools/doctor robot --npu-vlm-probe --help
tools/doctor robot --npu-act-bench --help

OPENBLAS_NUM_THREADS=1 OMP_NUM_THREADS=2 tools/doctor robot --npu-act-bench \
  --backend qnn --model .xlerobot/npu/act/export/act-float.onnx \
  --samples .xlerobot/npu/act/export/sample-*.npz \
  --duration 60 --rate 3 --output .xlerobot/npu/act/repeat.json
```

CPU 对照改成 `--backend cpu`。NPU 复现前需要实验环境和设备兼容链接；该工具
不会自动创建链接、装依赖或启用机器人。可在确认不存在同名设备时临时执行：

```bash
sudo ln -s /dev/adsprpc-smd-secure /dev/fastrpc-cdsp
# 完成离线推理后，仅删除自己创建的符号链接。
if [ "$(readlink /dev/fastrpc-cdsp)" = /dev/adsprpc-smd-secure ]; then
  sudo unlink /dev/fastrpc-cdsp
fi
```

内部导出脚本 `tools/lib/npu_act_export.py` 在 GPU 主机的既有 ACT Python 环境运行，
ONNX 工具装入独立 `--target` 目录；未修改原服务依赖。远程机器 DNS 当时不可用，
由 X1 从 PyPI 下载并校验 wheel 后复制过去，没有更改其 DNS 配置。

原始结果全部保留在忽略目录：

- VLM：`.xlerobot/npu/vlm/qwen25-evaluation.json`、`qwen25-pixel-evaluation.json`、
  `qwen25-final.json`、标注复查后的 `qwen25-reviewed.json`，包含失败输出、耗时、token 数和 IoU。
- ACT：`.xlerobot/npu/act/export/export-report.json`、`sample-*.npz`、
  `.xlerobot/npu/act/benchmark-{qnn,cpu}-{1,2,3}.json` 和 ORT profile。
- 模型、录像、图像、真实关节数据和机器日志均不提交。

从 `ros2_ws` 构建 `xlerobot_bringup` 成功；本轮新加 4 项软件测试，与原 NPU 工具
5 项一起共 **9 项通过**。覆盖框坐标单位转换、无效/空框与 JSON 拒绝、意图物品名
检查、ACT 输入契约，以及供应商服务器实际绑定回环地址。测试不访问 NPU 或电机。

下一步仍先实验：补 VLM 的歧义指令与独立物品测试；校验框选中心/尺寸是否满足
接近与抓取前的要求；为 ACT 增加更长的离线轨迹、夹爪边界、上下文缓存与冷启动
测量，再安排有人监护的实机验证。NPU 上能执行模型与能稳定完成抓取是两个验收层次。

本轮没有评价 ASR/VLM/ACT 的 NPU 并发、热稳定性与一小时混合任务；不能由单模型
成本直接相加推算整机负载，更不能宣布完整 demo 已经摆脱远程 GPU。

参考供应商的 [VLM 部署示例](https://docs.aidlux.com/en/software/tutorial/genai-dev/vlm_chat_aidgen)、
Qualcomm 的 [QNN EP 使用说明](https://github.com/onnxruntime/onnxruntime-qnn)及
[设备枚举源码](https://github.com/onnxruntime/onnxruntime-qnn/blob/main/onnxruntime/core/providers/qnn/soc_utils.cc)。
